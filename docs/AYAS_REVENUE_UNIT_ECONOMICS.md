# Revenue unit economics — Stage16.2

The management ledger records observations; it does not move money or provide statutory accounting. It has no platform client, credential, production binding or action authority. Profit leaves the Stage16.1 zero-spend budget unchanged.

`AyasRevenueLedger` defines immutable exact-key facts and SHA-256 identities. `AyasRevenueLedgerStore` requires an explicit checkout root and stores only `data/brain/revenue/ledger.json`, separately from production cost ledgers. Reads do not create directories. Maximum history is10,000 entries /16MiB; configured capacity may only be lowered. Capacity refuses new facts without deleting history; exact replays still return the original entry without writes.

Input fields are closed: bounded integer minor-unit magnitude, supported currency, platform/event, canonical UTC times, digest-only external/order/offer/activity/evidence identities, closed provenance and optional notes code. Raw names, contacts, messages, credentials, platform JSON, paths and extra fields cannot be persisted. Opaque external IDs may be bounded-normalized and hashed using `digestAyasRevenueExternalId`; every adapter must provide a distinct external digest for each economic fact (gross, fee, refund, etc.). No raw external identifier is stored. This schema does not claim the digest's preimage or provenance has been externally verified.

Identity uses platform, external digest, event, amount/currency and occurrence time. A repeat with identical economic/group/evidence fields returns the first recorded entry; property order and a later recording time do not change it. Any material difference on the same platform/external digest is CONFLICT, including provenance changes; no silent trust upgrade or overwrite. Refused conflicts are not ledger events, so aggregate conflictCount is null with NOT_RECORDED coverage, rather than an invented historical zero.

Corrections append an exact REVERSAL, followed by a new corrected fact with a new external digest. A target must exist, be an unreversed non-reversal, match platform, currency, amount and grouping digests, and precede the reversal's occurrence time. Two concurrent reversals cannot both commit. Historical rows are immutable; there is no deletion API.

Writes use the existing PID/start-time checked exclusive lock under the revenue root. The state/revision is read again under that lock. A private UUID temp file is exclusively created, written and fsynced before atomic rename. The reader rejects malformed history, invalid identities/reversal order, non-files, hardlinks, symbolic links/junction escapes and excessive bytes. SAFE_READ_ONLY / unavailable mode blocks before the first effect and again before publication. Sequential replays remain reads in safe mode. No caller-selectable ledger filename or environment override exists. The lock excludes cooperating writers; this is not a tamper-proof bank journal against a privileged filesystem editor.

Pure economics always separates currencies, including when grouping by platform/order/offer/activity/UTC day/Monday week/month. No FX or fractional money conversion occurs. Reversals are resolved against the whole history before time grouping. Payout is cash-flow only; withholding tax is a separate observed amount. Net revenue = gross minus refunds; variable costs = platform + processing + delivery + ads + other; observed contribution = net minus those costs. Safe-integer overflow refuses the aggregate.

Missing fee facts are unknown. A sale needs order-bound platform and processing fee observations from the same platform/currency; explicit zero-fee facts count. Otherwise status is INCOMPLETE and contributionProfit / margin are null; observedContributionProfit remains explicitly partial arithmetic. A positive observed subtotal cannot imply verified profitability or spend permission. Source coverage preserves OWNER_IMPORT / PLATFORM_ADAPTER / SYSTEM_DERIVED separately; all remain UNVERIFIED_OBSERVATIONS. COMPLETE_OBSERVATIONS describes schema coverage, not external truth certification. Margin is null when net revenue is nonpositive.

All writes occur in owned TEMP roots; live revenue data is fingerprinted before/after. Windows canonical-link test uses a directory junction; POSIX uses a file symlink. Independent review, affected security/regression, TypeScript, lint, diff and Graphify evidence are required before source closure.
