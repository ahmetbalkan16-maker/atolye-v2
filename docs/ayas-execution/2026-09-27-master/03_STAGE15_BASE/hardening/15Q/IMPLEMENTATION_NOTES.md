## 15Q.3 — host-common occupancy and consumer binding

Base `0c020e0`. The 15Q.1 governor and capacity lock and the 15Q.2 controller had no host context and no consumer. This packet adds the one shared source they read from and binds the existing consumers to it, without replacing Machine Health.

**The source.** `src/lib/ayas/machine/AyasResourceOccupancy.ts`: one advisory record per running workload under `data/brain/execution/resource-capacity/occupancy` of this checkout (git-ignored; a TEMP clone resolves its own root, so a test never sees the live one). A record carries an opaque id, a task id, a resource class, a production flag and the owning process's PID and start time; it is written with a temp file, fsync and rename, and removed when the workload ends. A reader classifies each record: RUNNING while the owning process is alive (PID and start time), STALE when it is gone, and UNCERTAIN when the dead owner was a heavy local model, whose runtime can outlive the process. An unreadable or malformed inventory is unknown (`null`), never empty. Reading creates and removes nothing. A record grants nothing: it can only make another workload wait.

**Production (`ProductionPipelineExecutionCanonicalRuntime.ts`, one call).** Every durable stage execution is published for its whole run (render class for visuals, animation, video and assembly; light class otherwise) and released on success, failure and refusal. Production has explicit priority, so the publication is advisory for production itself: a stage is never refused because its record could not be written or the inventory could not be read, and two production stages never exclude each other. One new refusal exists: a render stage is refused before durable preparation, at the same position as the existing pressure guard, while a local model is published as loaded (`RESOURCE_MODEL_RENDER_OVERLAP`) or its state is unconfirmed (`RESOURCE_UNCERTAIN_MODEL_DEPENDENCY`). No registered engine exists today, so nothing publishes such a record outside tests. The two Machine Health checks are unchanged. Production health and readiness read paths do not import any of this.

**Heavy capacity holders (`AyasResourceCapacity.ts`).** After winning the lock and the fresh reread, a heavy holder publishes itself, then looks at the inventory. Production publishes and looks the same way, so a render stage and a model starting at the same moment cannot both miss each other. A holder that cannot publish, or cannot read the inventory back, does not start (`RESOURCE_OCCUPANCY_UNPUBLISHED`, `RESOURCE_HEAVY_INVENTORY_UNKNOWN`); a non-production holder that finds a production stage defers with its task preserved (`RESOURCE_OWNER_OR_PRODUCTION_PRIORITY`).

**Heavy self-development (`scripts/ayas-discovery-daemon.ts`).** The discovery child now reads the owner's RAM admission policy (it used the default 90 whatever the constitution said — F31) and applies the shared inventory to its Machine Health decision before its lease: an active production stage, another heavy workload or an unreadable inventory turns the run's action into PAUSE, which the existing lanes already honour. It publishes and prunes nothing. The two sandbox lanes (novel patch, micro batch) started under `BLOCK NEW HEAVY WORK` — the owner RAM limit, critical pressure, an invalid or missing core sensor — because their gate named only PAUSE and STOP (F32). They now start only under ALLOW or THROTTLE.

**The governor's real context.** `collectAyasResourceContext` measures production activity and the heavy inventory from the records and a hardware fingerprint from CPU, core count, RAM and platform. Owner interaction, queue depth, loaded-model footprint, thermal state and host-protection events have no measured source and stay null/UNKNOWN, so the governor defers a new heavy local model start instead of admitting it on a guess; a published holder's own continuation is proven by its record. `readAyasCurrentResourceState` is the host provider for the capacity primitive. `scripts/ayas-resource-status.ts` is the read-only operator view (`--prune-stale` is its one write: old records whose process is gone; never an UNCERTAIN model record).

**Deliberately not bound.** (1) Governed, owner-approved source execution (`AyasExecutionRevalidation`) keeps its pressure check only: its one-shot authorization is reserved before the check, so a priority hold there would consume the owner's approval. (2) Operator-run heavy tools (eval baseline, build, Graphify, the local-coding qualification runner) are admitted by the operator under the PC-health rule, not by the governor; they are not published holders. (3) The observer tick's durable recovery sweep is a light read and stays on the raw Machine Health action. (4) The on-demand controller stays unwired: nothing but its smoke calls it.
