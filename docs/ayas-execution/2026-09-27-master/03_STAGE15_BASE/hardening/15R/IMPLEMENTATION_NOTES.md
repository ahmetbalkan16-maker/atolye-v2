Canonical requirement, verbatim in substance: one owner-visible action enters `SAFE_READ_ONLY`. Allowed: chat and status, read-only research. What the mode does not need: a new authority engine, a second approval state, a daemon. Entering only tightens, so the owner page and an operator CLI may both enter; leaving goes through the owner session alone.

Threat model, stated: "cannot be cleared by model, tool or research text" means no action on the allowlist, no tool, no discovery capability, no voice or UI path and no governed proposal can leave the mode; only the owner-session action can, after the health checks. A process with raw write access to the repository's `data/` tree is outside this boundary, as it is for the execution gate and the authorization store.

## 15R.1–15R.3 — implemented and validated as one source packet

The three planned packets touch the same files and were built together on base `4475e94`; they are committed as one source packet with one evidence set.

**The mode (`src/lib/ayas/safety/`).** The mode is the last event of one append-only, hash-chained log under this checkout's ignored `data/brain/execution/safe-mode`: an ENTER turns it on, an owner EXIT turns it off, nothing else is a state and no process keeps it in memory. The reader imports no session, writer or approval authority and fails closed: a log that cannot be read or does not verify (malformed event, unknown field, sequence not matching its file, gap, unexpected file, broken chain, wrong order, an EXIT that is not the owner's or has no passing health report, a store that is not a directory) is UNAVAILABLE, and every consumer treats UNAVAILABLE exactly like SAFE_READ_ONLY. Only a log that is verifiably absent, or whose last verified event is an owner EXIT, reads NORMAL.

**Entering and leaving.** Entering only tightens, so the owner page and the operator CLI can both enter; who entered is derived from the verified cookie session, never taken from the caller. Leaving is the owner's alone: `exitAyasSafeMode` verifies the session (`resolveAccessGate` enforced plus `verifySession`; `disabled-dev` is not owner authority) before the store is read and again before the EXIT is written, and requires every current health check to pass — owner constitution not UNAVAILABLE, both execution gates readable and CLOSED, Machine Health allowing a start, the Stage 15Q occupancy inventory readable. The checks are stored in the EXIT event. A log that does not verify is never appended to; the owner inspects it.

**Where it binds.**
- Action firewall, at every decision (issue, admit, owner bind, owner admit, discovery issue, discovery admit, each capability of a running discovery run): a read is issued and admitted in every state; bounded local work, a source write and a discovery run are refused, including a lease issued before the mode was entered. The mode is read from the log at each decision, so an entry by any process stops the next one.
- Approval and execution: the three approval entry points refuse before a decision is minted, and `executeApproved` refuses before the one-shot authorization is reserved, so a refusal does not consume the owner's approval.
- Production: no new stage is admitted (`executeDurableProductionPipelineStage`, before the occupancy and before durable preparation); `YouTubePublishPipeline.publishStoredPackage` refuses; the sixteen mutating production routes answer 423 with the reason before reading their body; `reserveProjectCost` refuses a new reservation while settling and releasing stay possible.
- Self-development: the discovery child holds its whole run before its ledger entry and lease (`SAFE_READ_ONLY_HOLD`); the self-heal CLI's two working-tree applies refuse.
- Owner page `/brain/safe-mode`: state, what stays open and what stops, the enter button, and in the mode the current health checks with the exit button. The exit form carries only the digest of the mode the owner was shown; the session comes from the cookie.

**Decisions worth knowing.**
- Chat, status, read tools and read-only research through chat stay allowed. The observer's scheduled research tick is held together with the rest of the discovery run: allowed is not required, and a held tick writes nothing.
- A stage that is already running is not interrupted: there is no safe cancellation contract for a stage handler, and admission is where Machine Health and the occupancy already sit.
- The mode is not an action. Nothing on the allowlist or among the reserved actions names it, no tool can enter or leave it, and the CLI has no exit.
- Threat model: no AYAS action, tool, discovery capability, voice or UI path and no governed proposal can leave the mode. A process with raw write access to the repository's `data/` tree is outside this boundary, as for the execution gate. A well-formed forged EXIT written directly into the log would be accepted; an EXIT that is not shaped like an owner exit is not.
- The console has no mode indicator yet; that belongs to Brain UI V2. The mode is visible on its page, in the CLI and in every refusal reason.

- 15R_OWNER_PAGE_E2E.json: a real `next start` in a TEMP clone (own build, own node_modules copy, own runtime and authority roots, a fixture key, a spare loopback port). One owner action entered the mode; the page showed five passing checks; a production route answered 423; exit was refused without the session, across origins, with a stale digest and with an extra form field; the owner exit wrote an EXIT with the five checks and the route answered normally again. The repository, its `.next`, the owner's server and the live mode were not touched.
- 15R_PRODUCTION_REGRESSION.json: 36 production-path, route and self-heal suites in an isolated TEMP clone with the packet overlaid — 26 PASS; nine fail exactly as at clean HEAD (F33); one refuses any layout but its own TEMP archive, at HEAD as well.
- Existing suites: firewall 54, owner capability firewall 32, closure 12, durable recovery 22, discovery registry 15, eval governance 10, resource occupancy 12, Machine Health 20; the affected declared suites through the TEMP-clone runner on the overlay (15R_FOCUSED.json). TypeScript, changed-file lint and diff check PASS. Manifest v32: 114 suites, 133 pins.
