# Revenue security / fraud — Stage 16.11

The closed revenue runner applies adapter policy, zero-cost/spend policy, then a refusal-only security guard before a read or local draft. It inspects normalized returned data before exposing it to context, drafts or memory consumers. All financial operations stay denied and all external writes stay owner-required and unexecuted. The production adapter registry remains empty. This packet adds no HTTP handler, connection, scheduled action, browser fallback or approval path.

External content is bounded plain data with descriptor preflight and one frozen snapshot. Detected instruction, fake-owner-approval, command/path, credential, payment diversion, malicious link and private-data content returns codes and a digest; raw risky text is discarded. Accepted data retains EXTERNAL_UNTRUSTED_TEXT classification. Detection is conservative pattern recognition, not proof that arbitrary natural language is harmless; operation/tool/path/payment selectors remain code-owned independently of detection. A caller or model cannot submit a severity downgrade or an owner approval to the guard.

HTTPS references require exact code-owned platform hostnames, no userinfo, unexpected ports, reset/redirect endpoints or redirect query selectors. References are never opened. Unqualified support/documentation hosts, unknown hosts, shorteners and cross-platform references remain blocked. A real owner-approved host extension requires separate qualification; no public input can extend this list.

Attachment intake accepts bytes only, never a URL or caller path. It refuses executables, scripts, macro containers, archives, traversal, unknown/mismatched MIME, oversize, malformed UTF-8, active PDF markers and detected secrets/PII/instructions. Closed document/media signatures only establish eligibility for quarantine. Eligible bytes are copied into a newly created contained TEMP root under a fixed generated filename, made read-only, re-read and checked, then removed. There is no document/archive parser or malware attestation. All archives and Office containers require a future qualified isolated parser; no manifest supplied by an attachment is trusted. No production attachment ingress is bound.

Account comparison consumes normalized metadata from a trusted official reader and refuses material account/shop/store/mode/scope/catalog/security/MFA/session/credential drift, future/old observations and unknown records. It never connects, rotates, logs a token or changes a password. OBSERVED_STABLE is advisory, not authentication. Production reader binding remains unqualified; platform adapters keep their existing independent connection and owner-controlled qualification gates.

Write binding compares the exact platform/account/resource/action/nonce and fresh canonical state against a bounded journal. Every prior outcome, including REJECTED and UNKNOWN, blocks blind retry and nonce reuse. A clean comparison still returns REQUIRE_OWNER_REVIEW, never approval or execution. Journal persistence/nonce consumption, idempotency support and current official reader qualification remain future owner-bound responsibilities. Existing explicit owner authority/binding paths are unchanged; digest and metadata equality do not authenticate an owner.

Etsy and Lemon wrappers reuse their actual platform HMAC verifiers. Signed notifications are pointers only. Etsy retains its signed five-minute window; Lemon provides neither a signed delivery timestamp nor a unique delivery ID, and this packet invents neither. The Lemon canonical refresh goes through the guarded GET runner and exact resource/store/mode checks; the security wrapper returns only an inert read digest. Webhooks cannot write ledger or execute. Durable ingress, dedupe, HTTP ACK, owner Test-mode qualification and actual owner account health remain unbound. Unsupported platforms fail closed.

The 16.2 ledger remains the sole realized-money truth; no expected revenue or security observation creates spend authority. Deterministic primary, frozen adversarial and independent assertion-caught mutation suites use synthetic signatures and fake adapters, with no network or real private messages. Test results do not qualify a live account, ingestion route, owner approval or payment. Graphify PARTIAL / semantic PENDING and inherited CF49 are carried explicitly; the full declared baseline status is recorded separately from focused tests.
