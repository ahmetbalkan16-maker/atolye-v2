# AYAS Stage 9 — Security / Supply-Chain Defense

Date: 2026-09-24. Baseline: published `2397edf0b55233d101668657f1451e37c5334fdf` on `wip/ayas-graphify-final-execution`. This sprint changes security checks around existing readers and writers; it adds no tool, agent, provider, dependency, approval path, or autonomous mutation kind.

## Security rule and attack surface

External text, model output, tool results, skill/MCP/agent metadata, packages, benchmark results and generated patches remain data. Executable authority comes only from checked-in registries, the session/owner decision, provenance binding and the existing execution gate.

| Surface / evidence | Input trust | Authority / effect | Boundary |
| --- | --- | --- | --- |
| `package.json`, lockfile, `node_modules` lifecycle scripts | package metadata untrusted until reviewed | installation-time code and native binary acquisition | reviewed lock, integrity fields, controlled install; no automatic install in AYAS |
| `AyasModelProfile`, `AyasModelRouter`, STT config, phone LLM model list | model responses/artifacts untrusted; environment is operator-controlled | local inference and browser cache; no model-generated process arguments | bounded names, real health probe, zero-cost policy, fixed phone model IDs, STT local file check |
| `AyasExecutionPolicy` → `AyasActionRuntime` → `AyasSafeExecutors` | model/tool proposal untrusted | registered read-only actions | own-key allowlist, plan/path validation, dispatcher and executor checks |
| Project-local skills; `.vscode/mcp.json`; Stage 7 agent selection | text/metadata untrusted | advice only; no AYAS skill/MCP/Claude/Codex adapter | no dynamic registration or dispatch from metadata |
| `AyasSafePublicFetch` → source registry → Stage 8 research loop | external URL/body untrusted | research findings and advisory hypotheses | registered sources, pinned DNS lookup, redirect recheck, size/type/time bounds, neutralized claims |
| `AyasResearchExperimentSandbox` → proposal bridge | trusted checked-in benchmark/strategy; finding text untrusted | TEMP experiment and owner-reviewable proposal | empty production strategy registry, protected paths, scope/evidence checks, no executable experiment mutation kind |
| `AyasMutationRegistry`, patch artifact and approval services | generated patch/proposal untrusted until bound | source write, commit/push only after owner/gate flow | exact files, base HEAD, patch digest, approval hash, stale/replay refusal |
| `AyasBoundedFileWrite`, repo source reader | path/file content untrusted | bounded source write or read | lexical rules plus symlink/junction refusal; atomic leaf replacement |
| AYAS chat/intake APIs and Unified Trace | session request untrusted | private conversation or durable intent intake; trace is observability only | auth/middleware CSRF, byte-bound JSON body, sanitized trace labels/codes/counts |

Repo searches covered dynamic import/require, `child_process`, PowerShell/cmd, filesystem writes, TEMP/clone/worktree/archive, outbound HTTP, JSON parsing, secret lookup, logs and AYAS API routes. No AYAS runtime MCP dispatch or external agent adapter was found. The editor's `.vscode/mcp.json` names a Graphify HTTP server; its result is outside AYAS execution authority. Graphify CLI is separately installed and was used for this review.

## Concrete threat model

| Asset | Threat / entry | Possible impact | Existing defense and verified gap | Severity / result |
| --- | --- | --- | --- | --- |
| Production source/runtime | linked path under approved write scope | write outside exact file scope | lexical scope accepted a junction; TEMP proof changed an outside fixture | **MAJOR fixed** by component checks, atomic leaf replacement and rollback on write-phase failure |
| Private repository files | linked path under `inspect-source-file` | disclose outside file as source text | lexical path/extension accepted a junction; TEMP archived route proof returned outside fixture | **MAJOR fixed** by linked-component refusal before read |
| Tool authority | model action named `toString` / `__proto__` | inherited property accepted as allowlisted tool | `in` tested prototype chain; clean-baseline evaluator returned `ok` | **MAJOR fixed** by own-key checks in policy, document enum and executor registry |
| API availability | authenticated oversized POST without `Content-Length` | unbounded JSON buffering | header-only limit parsed 33 KB / 257 KB fixtures before rejecting fields | **MAJOR fixed** by bounded stream reader on chat and intake |
| Research/proposal authority | hostile source claiming owner approval or giving commands | unauthorized mutation | finding normalization treats claim as data; Stage 8 injection, proposal and gate regressions pass | no verified gap |
| Local/network access | malicious public source/redirect/DNS answer | SSRF to localhost/metadata | `AyasSafePublicFetch` validates every hop and connected address; 24 offline cases pass | no verified gap |
| Patch replay | stale HEAD, changed scope/hash, duplicate decision | wrong or repeated source mutation | approval binding, staleness and execution journal; relevant regressions pass | no verified gap |
| Dependency/model supply chain | compromised package lifecycle or mutable model artifact | install-time code, poisoned local/browser model | locked tarball integrity; seven install-script packages; phone models fixed by ID but downloaded revision defaults to `main` | **MINOR/deferred**: controlled installs and revision/integrity work require separate artifact evidence |
| Local same-privilege racer | rename parent directory between component check and filesystem call | path escape despite check | no portable open-relative directory handle on this Windows Node path; no untrusted remote input can create that race via AYAS | **MINOR/deferred**; do not claim OS isolation from hostile local processes |

Severity is based on the demonstrated entry and reachable effect. The TEMP proofs never used a live secret or production data path.

## Dependency and installation audit

- Node `v24.18.0`, npm `11.16.0`; npm lockfile v3 with 558 package entries, all resolved tarballs from the npm registry, integrity fields present, no Git/URL tarball dependency in the lock. Fifteen direct dependencies/dev dependencies are installed with no `npm ls --depth=0` problems. The root package has no `preinstall`, `install`, `postinstall` or `prepare` hook. Eleven direct ranges use `^`; the lock pins their installed versions. Reproducibility depends on using the lockfile (`npm ci`) and trusting its registry/artifact source.
- Seven locked dependencies declare lifecycle scripts: `esbuild` (dev), `fsevents` (optional macOS dev), `onnxruntime-node`, `protobufjs`, `sharp`, `unrs-resolver` (dev), and `workerd` (dev). The installed `onnxruntime-node` postinstall fetches native packages from NuGet; `esbuild` and `workerd` include registry binary-download fallbacks. These are installation-time code paths, not AYAS runtime research actions. Review changes to these package versions and scripts before an install; do not silently run `npm audit fix` or bulk upgrades.
- Read-only `npm audit --offline --json` reported zero cached advisories. A live `npm audit` request failed in the sandbox and its escalated retry was **rejected by automatic approval review** because it would send project dependency metadata to the public npm registry without specific authorization. Therefore zero *current* vulnerabilities is **not established**. No package was installed or upgraded. A current advisory review requires explicit owner authorization for that metadata transfer.

## Model, tool, skill, MCP and agent trust

AYAS chat uses local Ollama only after a health probe. Invalid `AYAS_OLLAMA_MODEL` syntax falls back to the configured local model; no user/model text can choose a filesystem model path. The general cloud config can hold an operator-supplied HTTPS endpoint/key, but the AYAS model router refuses uncertain-cost cloud fallback. STT is off until operator-controlled executable/model paths resolve to local files; audio bytes never become shell arguments. Browser phone LLM models are a fixed three-ID list and are isolated from production chat, but their resource URL currently defaults to mutable revision `main` and lacks a pinned artifact digest; this is recorded for separate model-artifact work.

The tool registry is closed. Model text can suggest an intent but cannot register a tool, mark it writable, approve it or create an executor. `toString` and `__proto__` now fail as unknown tool IDs. The project-local `.claude/skills/ayas/*` files are guidance, not AYAS runtime registration. Stage 7's Graphify, Claude and Codex entries are descriptive/unregistered unless caller-owned availability evidence and an adapter exist; no live Claude/Codex dispatch was found. AYAS has no runtime MCP connector/command path, so `.vscode/mcp.json` does not turn an MCP response into a mutation.

## Research, commands, paths and sandbox

Research sources are checked-in registry entries. `AyasSafePublicFetch` limits protocol, host, DNS result, every redirect, content type, size, timeout and retries; it carries no auth cookie/header. The Stage 8 loop neutralizes and bounds quotes, detects English/Turkish directives, and never reads quoted text as a file, command, benchmark, strategy or approval. The production experiment strategy list remains empty. Tests verify injected approval/command text never acquires authority.

AYAS process sites use fixed executables with argument arrays (`execFile`/`spawn`) for Git, Node validators, local STT and OS probes. A Windows `cmd /c` call in post-publication closure executes a fixed Graphify command; no external research/model text is interpolated into it. Package lifecycle scripts are a separate install-time risk noted above. Path handling now rejects existing symlink/junction components for both bounded writes and source reads. Writes use a same-directory temporary file and rename so a late leaf symlink is replaced rather than followed; failures during a multi-file write enter rollback. A hostile local process racing parent-directory replacement remains outside this application-level guarantee.

Stage 8 experiments clone an exact HEAD under OS TEMP, strip provider credentials, set TEMP/home/runtime/authority to the run directory, remove the clone remote, bound child time, and reject escaped/protected change paths. The node_modules junction and shared Git object database are read dependencies. **This is not an OS security sandbox for arbitrary malicious checked-in JavaScript**; child code with the user's OS privileges could still access paths outside TEMP. The actual production registry has no runnable strategy, and findings cannot supply a script or executable code. Do not add an unreviewed strategy or benchmark and mistake environment isolation for hostile-code containment.

Patch artifacts carry exact scope and digest, proposals bind base HEAD and patch identity to the approval hash, and stale/changed objects are refused without transferring old approval. Experiment evidence is digest-bound to its baseline and proposal; its mutation kind is unregistered. Existing gate/journal recovery never automatically replays uncertain writes. No new replay mechanism was added.

## Secrets, logs and API boundary

No secret values were opened or printed. Tracked-path search found no `.env`/credential file. Pattern search flagged only ten `scripts/smoke-*` fixture files, not a committed key file. Live `memory/records.json` and both four-record usage ledgers retained their original hashes. Experiment children receive an allowlist environment without provider keys. Unified Trace accepts fixed component/operation labels, bounded numeric/boolean metadata and safe reason codes; it does not store prompt/research bodies or raw secrets. AYAS chat/intake routes verify session; middleware applies the existing same-origin check on state-changing protected requests. Their JSON bodies are now bounded by actual streamed bytes even when the sender omits or lies about `Content-Length`.
